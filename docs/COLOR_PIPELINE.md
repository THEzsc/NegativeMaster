# 负片转换：计算约定、影调建议与校准边界

本分支把输入解码、胶片反转与创作影调区分开来。自动建议提供可复核的起点，不声称从一张照片就测出了胶片特性。已有参数、预设和边车仍沿用原有数值含义；没有给旧作品额外套一遍 sRGB 编码曲线。

## 建议的操作顺序

1. 固定翻拍光源、相机曝光和白平衡，尽量使用 RAW 或保留完整位深的 TIFF。
2. 确认输入编码：普通 sRGB 图像选 `srgb`，已线性化的扫描选 `linear`，明确知道扫描软件使用幂函数编码时才填数值 gamma。文件扩展名不能决定传递函数。
3. 校平、裁切，再检查自动检测的可信程度。边缘不足时使用人工参考或保留手动结果。
4. 取未曝光片基、暗部及亮部样本，建立反转基础。片基可以位于最终裁切框外，现在始终从方向调整后的原幅图像取样。
5. 选取同卷、同翻拍条件下几张有细节的代表照片，分析统一 gamma。特殊夜景、雪景或舞台照片不宜独自决定整卷影调。
6. 审阅后共用一个 gamma，再按每张照片的意图调整曝光、高光、阴影、曲线和颜色。

darktable 的官方流程也把片基、密度范围与印相风格分开，并要求取样时排除灰尘和划痕；其文档给出拍摄光源白平衡与未曝光片基的准备方法。[darktable negadoctor 手册](https://docs.darktable.org/usermanual/development/en/module-reference/processing-modules/negadoctor/)

## 输入和位深

RAW 解码使用 rawpy 的线性输出 `gamma=(1, 1)`，关闭自动提亮，保留 16 位，输出 sRGB 原色。这里“sRGB 原色”和“sRGB 编码曲线”是两件事：数据仍为线性值。

普通图像先归一化为浮点数，再按输入设置解码。sRGB 使用分段函数，不能简单当成 `x ** 2.2`。其传递函数与原色定义可查 [ICC sRGB 注册资料](https://registry.color.org/rgb-registry/srgb)。

RGB 16 位 TIFF 现在使用 tifffile 读取，避免 Pillow 的 RGB 路径将其截为 8 位。平面排列 RGB、归一化浮点 TIFF、灰度、灰度加 alpha 和调色板图像都有明确处理；非有限数据会报错。浮点 TIFF 的约定为 `[0, 1]`，多维/多页图像不作为一幅胶片扫描处理。

当前非 RAW 路径假定 RGB 原色为 sRGB，没有实现任意输入 ICC 到工作空间的完整转换。Adobe RGB、ProPhoto、扫描仪设备空间等文件应先在色彩管理软件中转换到适合的 RGB 工作空间，并确认其传递函数。给导出文件嵌入 sRGB ICC 仅说明输出如何显示，并不代表完成了相机、光源、胶片染料的光谱校准。

## 两种反转引擎的含义

### 密度归一化

对每通道线性透过率 `T`，计算：

```text
D = -log10(max(T, 1e-5))
P = clamp((D - black_density) / (white_density - black_density), 0, 1)
rendered = P ** (1 / gamma)
```

黑白点可由片基/画面样本或百分位取得。这里的 `P` 是归一化密度，不是恢复后的场景线性光。逐通道百分位拉伸和灰世界白平衡都带有内容假设，强烈单色的画面可能需要手动取样或关闭灰世界白平衡。

本程序 `gamma > 1` 会提亮中间调；它是创作影调控制，不等于感光测定中的胶片 gamma。Kodak 将胶片 gamma 定义为特性曲线直线段的 `Δ密度 / Δlog曝光`；要测量它需要已知曝光、密度数据及处理条件。[Kodak 感光测定资料](https://www.kodak.com/content/products-brochures/Film/kodak-essential-reference-guide-for-filmmakers.pdf)

### negadoctor 风格印相

可选引擎使用相对片基的对数密度、`Dmax`、扫描偏移、印相黑点、相纸 gamma 和高光软压缩。项目额外用画面低透过率统计估计一个共享 RGB 曝光系数，因此这是项目自身的 negadoctor 风格实现，不是与 darktable 像素级一致的复刻。

`nd_gamma` 在印相幂函数中控制相纸反差，通常增大会压暗中间调，方向与普通 `gamma` 相反。自动建议直接评估该引擎的真实输出，不将两个数值混用，也不在其后额外套普通 gamma。正片、黑白模式使用自己的普通 gamma，不再受历史保存的 negadoctor 开关干扰。参数语义及官方实现可参考 [darktable negadoctor 源码](https://github.com/darktable-org/darktable/blob/master/src/iop/negadoctor.c)。

高光软压缩现在只对非负的高光超出量计算指数，避免在未选中的 NumPy 分支中溢出。合法极端 `Dmax` 和 softclip 设置有数值回归测试；无效的非有限参数、零密度范围或负 gamma 会明确报错。

## 自动 gamma 建议如何计算

实现位于 `conversion_advisor.py`，方法版本为 `robust-display-midtones-v1`。

- 输入是已正确解码的线性 RGB。分析最多采用约 384 像素长边的采样图，尊重方向、裁切、片基和白平衡设置。
- 使用相同的 `convert_base` 管线，关闭普通 gamma、对比度以及所有后续创作精调。不会更改源图、当前参数、缓存或边车。
- 先检查有效画面密度范围、输入通道截断、反转结果的中间调范围。空白、无细节、非有限、过小或严重截断的样本返回 `recommendation: null`。
- 以显示 RGB 加权值的第 35、50、65 百分位构造稳健中点，权重为 `0.25 / 0.5 / 0.25`。RGB 权重为 `0.2126 / 0.7152 / 0.0722`；此处是显示码值的明暗代理，不是场景线性亮度。目标 0.5 是产品选择的中间调起点，不是已知的 18% 灰卡。
- 普通 gamma 在 `[0.8, 2.8]` 内求解，先变换 RGB 再计算明暗统计，避免对彩色场景错误地交换幂函数与通道加权顺序。
- 相纸 gamma 在 `[1, 6]` 内搜索实际引擎响应，保留其高光压缩、曝光及白平衡顺序。
- 触及边界、截断或明暗特殊时降低可信度并给出提示，不无限扩大调整。参照直方图匹配开启时不提供不会生效的 gamma 建议。

“可信度”描述统计证据是否稳定，不是美学判断、颜色准确率或经过标定的概率。单帧最多给中等可信度；所有建议都应结合画面审阅。

## 为什么使用整卷统一值

`analyze_roll(reports)` 对每张有效照片等权，在 log-gamma 空间用中位数和 MAD 排除少数离群值，然后得到一个共同 gamma。图像分辨率、亮像素数量不会给某张照片额外投票权。不同反转引擎或胶片模式不会混合；不足 3 张或分歧过大时降低可信度，并报告接受/排除数量及四分位跨度。

应用统一 gamma 不会逐帧追平明暗，也不修改用户原有曝光与曲线。但旧引擎仍可能逐帧估计黑白点/灰世界白平衡；“统一 gamma”不等同于所有反转参数均已校准并锁定。要严格比较同卷曝光关系，应进一步使用共同片基、已测密度范围和一致白平衡。自然场景内容无法自行提供这些测量。

## 预览、导出和向后兼容

整幅预览里的 `stats_rect` 与真正裁切后的导出使用相同区域进行密度统计、灰世界白平衡和 negadoctor 自动曝光，片边不会再只在预览中影响这些统计。片基、暗部、亮部采样保留原幅坐标。

片框校平会剔除与片边共识角不一致的可疑主体线条，现在在剔除后重新计算保留边的置信。额外的 `geometry_confidence` 为平均边置信乘以实测边覆盖率，避免一条强边被误读为整个矩形都可靠。返回的提示明确区分本张实测、同卷参考与保留手动角度；参考结果不会冒充实测信心。这些诊断不改变原有裁切坐标、角度和横竖方向。

已保存的普通 gamma、曝光和曲线仍采用原来的显示影调语义。没有把旧版输出误当成场景线性光再施加 sRGB OETF，避免旧作品整体变亮。输出属于可显示的 RGB 成品，不应作为可测量的场景线性数据使用。本文所列 bug 修复可能使此前受 16 位截断、错误片基位置或预览统计范围影响的作品得到不同的正确计算结果。

## 验证与后续校准

`tests/test_conversion_advisor.py` 覆盖已知合成密度曲线的 gamma 恢复、特殊样本拒绝、非破坏性、裁切与片基、整卷离群值、相纸引擎真实响应、TIFF 位深和数值边界。原有自动校平/裁切测试继续验证小角度、边框、缺失边界、灰尘、主体线条干扰与手动参考的保守处理。

这些测试验证算法约定与回归，不是实拍胶片色彩认证。下一步建立实测样本集：同一光源/相机的阶梯曝光、灰卡与色卡、已知片基、不同乳剂和冲洗批次；记录曝光、解码设置及参考输出，再评估分通道特性曲线、色彩误差和人工偏好。当前没有充分样本支持“所有胶卷都自动还原准确”的结论。
